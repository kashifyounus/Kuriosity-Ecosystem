## 1. Declaration

KEP Framework v1.0.1 is approved as the controlled relocation successor to KEP Framework v1.0.0.

This release changes canonical repository and path coordinates. It does not alter the normative meaning or inventory of the eight KEP v1.0.0 governing instruments.

The release becomes effective only when the approved package is merged to `main`, repository visibility is verified consistent with KEP-001A UD-016, and post-merge verification passes.

## 2. Historical Integrity

KEP v1.0.0 remains historically authoritative at `kashifyounus/kuriosity-engineering-platform` with its original manifest and coordinates.

No v1.0.0 release record is amended by this declaration. Products already adopting v1.0.0 remain pinned to that release until they explicitly approve an upgrade.

## 3. Relocation Scope

v1.0.1:

- establishes the KE repository as KEP's successor canonical repository;
- establishes `platforms/kep/` as the canonical platform root;
- preserves the v1.0.0 normative inventory and document versions;
- incorporates relocation, parity, validation, and adoption evidence;
- records SNS_GATEWAY as the secondary validation context; and
- provides controlled upgrade and rollback guidance.

## 4. Release Gates

Effectiveness requires:

1. both founding repositories verified private;
2. KE-001 through KE-004 ratified and effective;
3. SNS_GATEWAY secondary-context validation recorded;
4. migration parity and historical-coordinate integrity verified;
5. the authoritative manifest and adoption guidance published;
6. the approved branch merged to `main`; and
7. post-merge verification recorded.

## 5. Non-Authorization Before Effectiveness

Before the effective state is recorded, products shall not claim adoption of v1.0.1 or use its proposed coordinates as effective contractual adoption coordinates.
